# Constraints

Rules for future work. Each line is the rule an accepted fix implies; the bracket says what caused it. Read at the start of every tick and before writing any brief, task or script. A missing rule shows up as a question to Fraser that this file should have answered: add the line.

## Build and merge

- Merge copies tie_word_embeddings from the base config and carries lm_head when untied. (9B gate 1, KL 12.3)
- No committed binary without its source in the same commit; the panel compares repo and box hashes. (pre-filebuf ELF, stale eth.elf)
- Every rebuilt binary matches its committed bytes in every loaded section, checked by `scripts/provenance.py` locally and in CI. (provenance task)
- A tool's default that names an artefact resolves at call time, never at import. (`path=ELF` bound at definition: a false gate 1 pass)
- Gate scripts exit nonzero on failure; a gate is read by its verdict line and its exit code together. (`eth.py` exited 0 on GATE 1 FAIL; textcheck too)
- A gate's expected value comes from an evaluator independent of the firmware's parser; an oracle that copies the firmware's tokenizer inherits its bugs. Unary `-(E)` is a wrapped `(0-(E))`, asserted after every binary operator, nested, and at the u256 boundaries in decimal and hex. (eth's bare `0-E` desugar computed `5 - -(3)` as 2; the Python oracle mirrored it and gate 1 passed; the Solana lane found it)

- A firmware helper that writes its output before it finishes reading its inputs (u256 sub, sub_borrow, shl, shr, sar, divmod) is never called with an output that is also an input; `tests/test_rv_eth_alias.py` checks every call. (the Solana lane's u128_sub_borrow, narrowed from eth's u256_sub_borrow, read `a` after writing `r` when `r == a`; eth has the same helpers but no aliased call)

## Oracles, gates and tests

- The oracle is the external library; the firmware moves to match it, never the reverse. (quirk-mirroring harness)
- Every fixture is gated against its oracle before anything uses it. (hand-written ERC-20 stub)
- Inputs the firmware rejects by design are asserted as errors, not compared. (strict bytes32)
- Gate 1 includes boundary values for every typed width, decimal and hex. (int256 at 2^255)
- Gate 1 includes over-window cases whenever a path makes them reachable. (spill)
- A test that guards a fix is shown to fail on the unfixed artefact before it counts. (spill test compared printed text and passed on the bug)
- Lockstep checks compare whole traces, not printed output. (bridge read the capture before eth_in: GPU lock error at position 8)
- A test of a feature checks the answer, not only that the mechanism ran. (spec spill test passed while the tool answered error)
- Tests run through the real driver path, not a hand-built one. (TEXT layout, boot via torch)
- A reference used for replay holds the same state as the circuit, store included. (replay of a loaded snapshot started from an empty store)
- An oracle or check of independence is proven by a seeded failure it must catch. (flipped keccak constant; planted errors in restatement review)
- Every gate log records torch, transformers, fla, triton and driver versions; one pinned venv for gates and evals. (vLLM install changed torch)

## Data and fine-tuning

- Structured files are generated by script, never hand-written. (smoke JSON)
- Knowledge training answers are complete source lines; facts are string-checked, phrasing may be generated. (cut answers)
- Stored text is split only where the source has a line end or a space; a read equals the source up to line wrapping. (store added a newline every 100 tokens: `0\n.93 ETH`)
- A store pack leaves free chunks for the model's own writes. (pack filled 512 of 512 with `put` offered)
- Generated answers are checked by script for every rule that can be checked, and by a reviewer whose catch rate is measured on planted errors. (checklist voice slipped past the first checker; reviewer caught 7 of 8)
- One answer shared by several question phrasings fits each phrasing: no yes or no on a wh- question. (`No,` answering `Why ...?`)
- A data family with a rejection count gets its rejections read, not just counted. (create2 always failed on a short salt, hidden as over-window)
- Training data teaches what not to call as well as what to call, from misuse seen in evals. (`run` given a fork address)
- Fine-tune gates measure capability loss, not distance from base. (0.0012 cap)
- A fine-tune trains against drift directly: a KL-to-stock term on general text, not only a smaller adapter. (ft1 KL 0.075)
- A training run saves weights at fixed step intervals and each epoch; it is resumable from the last save. (VM stopped at step 280 on credit)

## Evals and runs

- The eval harness runs on x86 beside the model server; no tunnels to laptops. (Docker, arm64)
- A run kills nothing it didn't start and uses a time limit that fits the work. (chat "hang" killed at 90 s)
- A test's length cap exceeds the longest legitimate answer it can produce. (smoke at 400 tokens cut file reads off)
- A run's time limit covers its worst case, every item at its cap, and it writes results as it goes so a timeout keeps what ran. (ft1 smoke hit its 2-hour limit at 15 of 20 and wrote nothing)
- An evaluation is sized to the time and credit available before it starts: a fixed sample per family, the same sample for every model compared. (ft1's full evaluation: about 2 minutes a row, 246 rows)
- Task lists that feed one arm are deduplicated by task name before launch. (Internet+Skills lists overlapped once the RPC was set)
- A server-side system line joins the client's system message; the template allows one. (TemplateError on every OpenCode trial)
- A first trial of any new arm is read before the batch is left alone. (two Internet+Skills false starts)
- A wait loop never matches a pattern its own command line contains. (loops that waited on themselves)
- A long run on rented capacity checks the account can pay for it. (VM stopped on zero credit mid-training)

## Reporting and publishing

- Every number in a report has a log path beside it. (unverified claims)
- A claim about what a run did is read from that run's artefact, not inferred from timing. (my own server check reported as the first in-trial circuit run)
- Fraser approves publishing and anything on the never-do list; everything else is decided here and recorded in Part 2. (Fraser, 2026-11-02)
- A deploy folder has an ignore list admitting only named files before its first deploy. (Vercel `.env.local` in the first console deploy)
- A step that publishes runs only when nothing held back would go with it. (console push would have published an unverified merge)
- A dependency between tasks names the artefact that crosses between them; with none, they run in parallel. (baseline eval, Act test, data generation waited needlessly)

## Task generation

- A generated task counts only after the harness's own `free-check` on x86: the reference solution scores 1 and doing nothing scores 0. (Fraser: each task proven solvable before it counts)
- A task's starting files hold no copy of the answer: no git history, no source tests, no original file. (a fresh OpenZeppelin clone carries both)
- Generated names are valid Docker image tags: lowercase words joined by single hyphens. (`oz-base64-_encode` failed `docker compose`)
- Task folders sent from the Mac carry no macOS metadata: `COPYFILE_DISABLE=1`, `--no-xattrs`. (lint failed on `._` files)
- Generated tasks keep our own namespace; a lint rule that requires another organisation's name is satisfied on a scratch copy, never by relabelling. (`[task].name must use the buidlguidl org`)
- A scorer judges the decisive call (the right file read, the right command), whatever comes before it, and compares spilled calls on their full command. (ft1's `files` and `run` rows were marked wrong for listing first and for spill's rewritten command)
- A scorer change is applied to every model compared, by rescoring saved rows, never only to the next run. (scorer fixed after ft1's run)
- A Dockerfile step runs as the image's own user; the chain image already runs as `agent`. (`su agent` asked for a password and every task build failed)
- A task's test suites never share a test function name; the local pre-filter rejects such a task before proof. (ETH Evals' `forge_checks.py` refused 3 dragonfly tasks: `Duplicate Forge check 'test_canCallWithValue'`)
- Overloaded test functions count as repeated names too: the verifier drops the arguments before comparing. (all 15 Solady tasks refused: `Duplicate Forge check 'testBase58EncodeDecode'` within one suite)
- Agent-visible task text avoids the lint's banned words (epoch, grader, rubric, score, benchmark, eval, being tested); the generator rejects such a candidate. (Solady `EmberUtils.sol` failed lint on `epoch`)
- Repeated test names in a task's own test file are numbered, and a helper's inherited test functions lose the `test` prefix; renaming never touches a name after a dot. (Solady gave 0 tasks: overloaded fuzz tests, `TestPlus.test__codesize` in every suite, and `x.offset` renamed to `x.gamma1`)
- One generated task per function name per file; overloads and numbered twins count as one. (Kind 2's first run planted the same check in three `_insert` overloads and in `extract_2_1` and `extract_4_1`)
- A run saves every field a later rescore needs, uncut: the final answer, the full command. (ft1's rows kept 2,000 characters, which cut answers after long file reads)
- A final answer is judged only on the model's words after a closed tool answer; a turn cut inside a file read has no final answer. (the scorer searched the whole turn, file text included, and passed ft1b file rows that never answered)
- An evaluation's token limit covers the longest file the model may read, as the knowledge test's does. (tool evaluation ran at 1,500 tokens; files run to 6,382)
- A gate script's later step never overwrites a finished result of the same name; copy first or name by checkpoint. (the ft1b gates reran the untrained evaluation and wrote the Ethereus test into `ft1/`)
